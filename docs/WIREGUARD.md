# WireGuard на Nintendo Switch

## Настройка

Готовую сборку Switch можно скачать со страницы [GitHub Releases](https://github.com/infriker/Moonlight-Switch-Wireguard/releases).

Скопируйте собранный `.nro` в каталог `switch` на SD-карте и запускайте его через hbmenu в полном режиме приложения (title takeover). Старую версию можно сохранить отдельным файлом; каталог настроек остаётся `switch/Moonlight-Switch`.

Поддержка WireGuard встроена только в сборку для Nintendo Switch. В настройках Moonlight включите WireGuard, укажите путь к конфигурации и IPv4-адрес компьютера с Sunshine в домашней сети. Если путь оставить пустым, используется `sdmc:/switch/Moonlight-Switch/wg0.conf` на SD-карте. Настройки сохраняются сразу, но применяются после полного перезапуска приложения.

Добавьте компьютер в Moonlight вручную по тому же IPv4-адресу. Через VPN доступны только соединения Moonlight к указанному адресу компьютера и стандартным портам GameStream. Остальной трафик Switch через туннель не перенаправляется.

Конфигурационный файл использует формат WireGuard с одной секцией `[Interface]` и одной `[Peer]`. Поддерживаются IPv4-адреса и один peer. Пример ниже — шаблон, а не готовый профиль: адреса `10.77.0.*` и `192.168.50.*` вымышлены, домен `.invalid` и строки `REPLACE_...` заведомо ненастоящие. Замените ключи данными отдельного профиля Switch, а Endpoint — адресом или hostname вашего WireGuard-сервера.

```ini
[Interface]
PrivateKey = REPLACE_WITH_SWITCH_PRIVATE_KEY
Address = 10.77.0.2/32
DNS = 192.0.2.53
MTU = 1280

[Peer]
PublicKey = REPLACE_WITH_ROUTER_PUBLIC_KEY
# Оставьте PresharedKey закомментированным, если роутер не выдал такой ключ.
# PresharedKey = REPLACE_WITH_OPTIONAL_PRESHARED_KEY
Endpoint = vpn.example.invalid:51820
AllowedIPs = 10.77.0.0/24, 192.168.50.0/24
PersistentKeepalive = 25
```

Поддерживаются ключи `PrivateKey`, `Address`, `DNS`, `MTU`, `PublicKey`, `PresharedKey`, `Endpoint`, `AllowedIPs` и `PersistentKeepalive`. Значения ключей укажите из своего WireGuard-профиля; не добавляйте ключи в настройки Moonlight. Приватный ключ хранится только в указанном конфигурационном файле: файл настроек Moonlight хранит флажок, путь и IPv4-адрес. `DNS` принимается для совместимости, но клиент его не применяет. Порт WireGuard задаётся в `Endpoint`; по умолчанию MTU равен 1280, допустимое значение в конфигурации — от 576 до 1420.

Не путайте два адреса в конфигурации и настройках:

- `Address` в профиле WireGuard — VPN-адрес самого Switch. В шаблоне выше это вымышленный `10.77.0.2/32`.
- `PC IPv4` в настройках Moonlight — LAN IPv4 компьютера с Sunshine. Для примера выше это мог бы быть вымышленный `192.168.50.25`.

Добавьте компьютер в Moonlight вручную по тому же LAN IPv4, который ввели в `PC IPv4`. Подсеть этого компьютера должна входить в `AllowedIPs`; роутер должен маршрутизировать пакеты между VPN-клиентом Switch и домашней LAN и иметь обратный маршрут к VPN-адресу Switch. После изменения флажка WireGuard, пути или `PC IPv4` полностью перезапустите Moonlight. Перезапуска приложения достаточно; существующее pairing обычно сохраняется и его не нужно выполнять заново.

Используйте отдельный профиль и пару ключей для Switch, экспортированные роутером. Не копируйте на консоль приватный ключ другого WireGuard-клиента, например ноутбука. Проверьте, что роутер разрешает трафик от адреса Switch в VPN-подсеть или домашнюю LAN и знает обратный маршрут к адресу клиента. Для Sunshine не требуется открывать игровые порты в публичный Интернет: нужен только доступ от WireGuard-клиента через роутер.

Используются только стандартные порты GameStream:

- TCP: `47989`, `47984`, `48010`, `47995`, `47999`.
- UDP: `47998`, `48000`, `47999`, `48002`, `48010`.

Клиент устанавливает отдельные локальные relay-соединения для этих пяти TCP- и пяти UDP-портов. Другие адреса и порты через WireGuard не перенаправляются. Если VPN включён, ошибка туннеля или relay не приводит к прямому подключению в обход VPN.

### Если есть handshake, но Moonlight не подключается к ПК

Handshake подтверждает обмен ключами с WireGuard-сервером, но не доказывает, что Switch может достичь LAN-компьютера. Проверьте, что роутер пропускает трафик от VPN-адреса Switch к LAN-адресу ПК, а у ПК есть обратный маршрут к VPN-подсети.

На роутере проверьте правила межсетевого экрана для интерфейса WireGuard. Для Sunshine со стандартными портами разрешите подключения от VPN IPv4-адреса Switch (в шаблоне это вымышленный `10.77.0.2`) к LAN IPv4 компьютера по следующим портам:

- TCP: `47984`, `47989`, `48010`.
- UDP: `47998–48000`, `48002`, `48010`.

Правила, созданные для ноутбука или телефона, могут не включать адрес нового Switch peer. Например, разрешение для `10.77.0.2/31` охватывает адреса `.2` и `.3`, но не `.4`. Добавьте правило для фактического VPN-адреса Switch. Также проверьте входящие правила Windows Firewall для Sunshine: они должны допускать этот источник и перечисленные порты, а не только локальную подсеть. Общий список relay выше шире: дополнительные TCP-порты предусмотрены для совместимости с другими версиями GameStream и не требуются для этого набора стандартных портов Sunshine.

Ограничьте разрешения адресом Switch, адресом ПК и нужными портами. Не открывайте эти порты для всего публичного Интернета. Порт веб-панели Sunshine `47990` для Moonlight не требуется.

Если Moonlight показывает `WireGuard mode only connects to the configured PC IPv4`, проверьте поле `PC IPv4` в настройках WireGuard. Оно должно содержать LAN IPv4 компьютера с Sunshine и совпадать с адресом, который вы выбираете в `Add Computer`. Добавление ПК только в `Add Computer` не заполняет поле `PC IPv4` автоматически. После исправления полностью перезапустите Moonlight. Если ПК уже был paired, повторное pairing обычно не нужно.

### Размер потока и режим дисплея Windows

Выбор 720p/60 задаёт параметры видеопотока `1280×720 при 60 FPS`; сам по себе он не гарантирует смену режима дисплея Windows. В Sunshine должны быть настроены нужный дисплей и автоматическое переключение его разрешения. Для автоматической смены разрешения Sunshine также требует включить в Moonlight «Используйте оптимальные игровые настройки» (`Use Streaming Optimal Playable Settings`). Если используется Virtual Display Driver и Sunshine сообщает об ошибке подготовки режима дисплея, проверьте, что в поддерживаемые режимы виртуального дисплея добавлен `1280×720 @ 60 Hz`.

Для Virtual Display Driver от VirtualDrivers режимы задаются в `vdd_settings.xml` или через companion tool. Добавьте 1280×720 с частотой 60 Hz, сохранив остальные режимы, затем перезапустите виртуальный драйвер через его инструмент управления или отключите и включите именно Virtual Display Driver в диспетчере устройств. Перезагрузка Windows также применяет изменения. После этого завершите старую сессию и запустите приложение на ПК заново из Moonlight, чтобы Sunshine повторил выбор режима. См. [инструкцию драйвера](https://github.com/VirtualDrivers/Virtual-Display-Driver/wiki/How-to-configure-the-driver) и [настройки дисплея Sunshine](https://docs.lizardbyte.dev/projects/sunshine/latest/md_docs_2configuration.html).

### Завершение сессии

Во время потока откройте overlay комбинацией `−` и `+` одновременно; сочетание можно изменить в настройках. `Disconnect` («Отключиться») завершает трансляцию и возвращает в Moonlight, оставляя приложение на ПК работать. `Terminate app` («Завершить приложение») также просит Sunshine завершить запущенное приложение на ПК. Это не выход из самого Moonlight на Switch.

## Ограничения

- Запускайте Moonlight как полноценное приложение Switch, например через title takeover; режима hbmenu applet недостаточно для фоновых потоков и памяти backend.
- Обнаружение компьютеров через mDNS и Wake-on-LAN через VPN не выполняются. Добавьте Sunshine-компьютер вручную по его IPv4-адресу.
- Весь сетевой трафик Switch не маршрутизируется через VPN; туннель обслуживает только перечисленные GameStream-соединения к одному компьютеру.
- IPv6 и несколько WireGuard peers не поддерживаются. Клиент использует стандартные порты GameStream; нестандартные GameStream-порты недоступны. Порт самого WireGuard-сервера можно указать в `Endpoint`.
- Изменение флажка, пути или адреса требует перезапуска Moonlight. Активная сессия не переключается на лету.
- После выхода консоли из сна или смены Wi-Fi перезапустите Moonlight: эта версия не восстанавливает туннель автоматически.
- Статус сообщает о готовности handshake и relay, но сам по себе не подтверждает, что роутер или компьютер доступны в данный момент.

## Сборка

Сборке нужны devkitPro/devkitA64, Switch toolchain и зависимости Moonlight, предусмотренные проектом. Инициализируйте только `wg-nx` и его подмодуль lwIP:

```sh
git submodule update --init --checkout extern/wg-nx
git -C extern/wg-nx submodule update --init library/lwip
cmake -S . -B build/switch -DPLATFORM_SWITCH=ON -DUSE_DEKO3D=ON -DENABLE_WIREGUARD=ON
cmake --build build/switch --target Moonlight.nro --parallel
```

Корневой CMake-проект настраивает Deko3D для Switch автоматически; `-DUSE_DEKO3D=ON` в примере указан явно. Цель `Moonlight.nro` создаёт файл приложения для консоли.

В официальном контейнере devkitPro предварительно удалите пакет `switch-enet` из контейнера (`dkp-pacman --noconfirm -R switch-enet`), как это уже делает workflow проекта. Moonlight использует собственную версию ENet; заголовки пакета из SDK с ней несовместимы.

Не используйте `--recursive` для `extern/wg-nx`: его тестовые подмодули содержат отдельные зависимости, включая Borealis по SSH, которые для клиента не нужны.

Переносимые тесты конфигурации и маршрутизации WireGuard собираются на Linux без Switch SDK:

```sh
cmake -S tests -B build/wireguard-tests
cmake --build build/wireguard-tests --parallel
ctest --test-dir build/wireguard-tests --output-on-failure
```

Подробнее о включённых компонентах и лицензиях см. [THIRD_PARTY_WIREGUARD.md](THIRD_PARTY_WIREGUARD.md), о локальных изменениях backend — [WG_NX_PATCHES.md](WG_NX_PATCHES.md), о выполненной сборке и тестах — [WIREGUARD_VALIDATION.md](WIREGUARD_VALIDATION.md).

## Проверка на консоли

На реальной Switch уже подтверждены успешный handshake и загрузка списка игр после настройки firewall. Это не подтверждает длительную работу игрового потока или все сценарии восстановления соединения.

Для полной проверки на консоли:

1. Подключите Switch к внешней сети, например к точке доступа телефона. Запустите Moonlight в полном режиме приложения с WireGuard, проверьте handshake и список игр. Для нового клиента проверьте также pairing через PIN в Sunshine.
2. Запустите игру или рабочий стол через WireGuard. Проверьте видео, звук и управление, затем оставьте поток работать не менее десяти минут, чтобы проверить несколько смен сеансовых ключей. Несколько раз запустите и остановите поток.
3. Временно сделайте VPN-сервер недоступным и убедитесь, что клиент показывает ошибку и не устанавливает прямое соединение с ПК.
4. Проверьте восстановление после сна и смены Wi-Fi; для текущей версии ожидается полный перезапуск Moonlight. Отдельно проверьте обычное LAN-подключение при выключенном WireGuard.

Длительная внешняя трансляция, ротация/rekey во время потока и восстановление после сна или смены Wi-Fi пока не подтверждены. Эти проверки требуют реальной консоли и вашего профиля; локальная компиляция и portable-тесты их не заменяют.
