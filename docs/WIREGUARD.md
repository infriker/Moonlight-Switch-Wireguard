# WireGuard на Nintendo Switch

## Настройка

Скопируйте собранный `.nro` в каталог `switch` на SD-карте и запускайте его через hbmenu в полном режиме приложения (title takeover). Старую версию можно сохранить отдельным файлом; каталог настроек остаётся `switch/Moonlight-Switch`.

Поддержка WireGuard встроена только в сборку для Nintendo Switch. В настройках Moonlight включите WireGuard, укажите путь к конфигурации и IPv4-адрес компьютера с Sunshine в домашней сети. Если путь оставить пустым, используется `sdmc:/switch/Moonlight-Switch/wg0.conf` на SD-карте. Настройки сохраняются сразу, но применяются после полного перезапуска приложения.

Добавьте компьютер в Moonlight вручную по тому же IPv4-адресу. Через VPN доступны только соединения Moonlight к указанному адресу компьютера и стандартным портам GameStream. Остальной трафик Switch через туннель не перенаправляется.

Конфигурационный файл использует формат WireGuard с одной секцией `[Interface]` и одной `[Peer]`. Поддерживаются IPv4-адреса и один peer. Пример ниже — шаблон, а не готовый профиль: адреса `10.8.0.*` и `192.168.1.*` приведены для примера домашней LAN, домен `.invalid` и строки `REPLACE_...` заведомо ненастоящие. Замените ключи данными отдельного профиля Switch, а Endpoint — адресом или hostname вашего WireGuard-сервера.

```ini
[Interface]
PrivateKey = REPLACE_WITH_SWITCH_PRIVATE_KEY
Address = 10.8.0.2/32
DNS = 1.1.1.1
MTU = 1280

[Peer]
PublicKey = REPLACE_WITH_ROUTER_PUBLIC_KEY
# Оставьте PresharedKey закомментированным, если роутер не выдал такой ключ.
# PresharedKey = REPLACE_WITH_OPTIONAL_PRESHARED_KEY
Endpoint = vpn.example.invalid:51820
AllowedIPs = 10.8.0.0/24, 192.168.1.0/24
PersistentKeepalive = 25
```

Поддерживаются ключи `PrivateKey`, `Address`, `DNS`, `MTU`, `PublicKey`, `PresharedKey`, `Endpoint`, `AllowedIPs` и `PersistentKeepalive`. Значения ключей укажите из своего WireGuard-профиля; не добавляйте ключи в настройки Moonlight. Приватный ключ хранится только в указанном конфигурационном файле: файл настроек Moonlight хранит флажок, путь и IPv4-адрес. `DNS` принимается для совместимости, но клиент его не применяет. Порт WireGuard задаётся в `Endpoint`; по умолчанию MTU равен 1280, допустимое значение в конфигурации — от 576 до 1420.

В настройке Moonlight укажите IP компьютера Sunshine. Например, в домашней LAN из примера выше это может быть `192.168.1.50`; это только пример, используйте фактический адрес вашей сети. В `AllowedIPs` должна входить подсеть этого компьютера. Роутер также должен маршрутизировать трафик от адреса WireGuard-клиента к компьютеру и пропускать игровые порты.

Используйте отдельный профиль и пару ключей для Switch, экспортированные роутером. Не копируйте на консоль приватный ключ другого WireGuard-клиента, например ноутбука. Проверьте, что роутер разрешает трафик от адреса Switch в VPN-подсеть или домашнюю LAN и знает обратный маршрут к адресу клиента. Для Sunshine не требуется открывать игровые порты в публичный Интернет: нужен только доступ от WireGuard-клиента через роутер.

Используются только стандартные порты GameStream:

- TCP: `47989`, `47984`, `48010`, `47995`, `47999`.
- UDP: `47998`, `48000`, `47999`, `48002`, `48010`.

Клиент устанавливает отдельные локальные relay-соединения для этих пяти TCP- и пяти UDP-портов. Другие адреса и порты через WireGuard не перенаправляются. Если VPN включён, ошибка туннеля или relay не приводит к прямому подключению в обход VPN.

## Ограничения

- Запускайте Moonlight как полноценное приложение Switch, например через title takeover; режима hbmenu applet недостаточно для фоновых потоков и памяти backend.
- Обнаружение компьютеров через mDNS и Wake-on-LAN через VPN не выполняются. Добавьте Sunshine-компьютер вручную по его IPv4-адресу.
- Весь сетевой трафик Switch не маршрутизируется через VPN; туннель обслуживает только перечисленные GameStream-соединения к одному компьютеру.
- IPv6 и несколько WireGuard peers не поддерживаются. Клиент использует стандартные порты GameStream; нестандартные GameStream-порты недоступны. Порт самого WireGuard-сервера можно указать в `Endpoint`.
- Изменение флажка, пути или адреса требует перезапуска Moonlight. Активная сессия не переключается на лету.
- После выхода консоли из сна или смены Wi-Fi перезапустите Moonlight: эта версия не восстанавливает туннель автоматически.
- Статус сообщает о готовности handshake и relay, но сам по себе не подтверждает, что роутер или компьютер доступны в данный момент.
- Сборка и portable-тесты проверяют исходный код, но в рамках текущей проверки работа на реальной Switch-консоли не подтверждена.

## Сборка

Сборке нужны devkitPro/devkitA64, Switch toolchain и зависимости Moonlight, предусмотренные проектом. Инициализируйте только `wg-nx` и его подмодуль lwIP:

```sh
git submodule update --init --checkout extern/wg-nx
git -C extern/wg-nx submodule update --init library/lwip
cmake -S . -B build/switch -DPLATFORM_SWITCH=ON -DUSE_DEKO3D=ON -DENABLE_WIREGUARD=ON
cmake --build build/switch --target Moonlight.nro --parallel
```

Корневой CMake-проект настраивает Deko3D для Switch автоматически; `-DUSE_DEKO3D=ON` в примере указан явно. Цель `Moonlight.nro` создаёт файл приложения для консоли.

В официальном контейнере devkitPro предварительно удалите пакет `switch-enet` из контейнера (`dkp-pacman --noconfirm -R switch-enet`), как это уже делает workflow проекта. Moonlight использует собственную версию ENet; заголовки пакета из SDK с ней несовместимы.

Не используйте `--recursive` для `extern/wg-nx`: его тестовые подмодули содержат отдельные зависимости, включая Borealis по SSH, которые для клиента не нужны.

Переносимые тесты конфигурации и маршрутизации WireGuard собираются на Linux без Switch SDK:

```sh
cmake -S tests -B build/wireguard-tests
cmake --build build/wireguard-tests --parallel
ctest --test-dir build/wireguard-tests --output-on-failure
```

Подробнее о включённых компонентах и лицензиях см. [THIRD_PARTY_WIREGUARD.md](THIRD_PARTY_WIREGUARD.md), о локальных изменениях backend — [WG_NX_PATCHES.md](WG_NX_PATCHES.md), о выполненной сборке и тестах — [WIREGUARD_VALIDATION.md](WIREGUARD_VALIDATION.md).

## Проверка на консоли

1. Подключите Switch к внешней сети, например к точке доступа телефона. Запустите клиент в полном режиме приложения, включите WireGuard с отдельным профилем Switch и перезапустите клиент.
2. Нажмите строку статуса, чтобы обновить её. После успешного handshake добавьте домашний IPv4 компьютера вручную, выполните pairing и проверьте загрузку списка приложений и обложек.
3. Запустите игру или рабочий стол. Проверьте видео, звук, управление и минимум десять минут непрерывной работы, чтобы захватить несколько смен сеансовых ключей. Повторите запуск и остановку потока несколько раз.
4. Временно сделайте VPN-сервер недоступным и убедитесь, что клиент показывает ошибку и не устанавливает прямое соединение с ПК. После сна или смены сети перезапустите приложение. Отдельно проверьте обычное LAN-подключение с выключенным WireGuard.

Эти проверки требуют реальной консоли и вашего профиля. Локальная компиляция и автоматические тесты их не заменяют.
